02 · Final build

Meet the robot

Our competition-day build kept the controls accessible while protecting the electronics inside a lightweight printed shell.

How the sensors work

Light becomes a steering error

The front photoresistor array measures reflected light across the track. After calibration, the code compares the readings, estimates where the dark line sits relative to the robot's center, and produces an error value. The PID controller turns that error into different left- and right-motor speeds, continuously steering the robot back toward the line.

03 · Control

PID tuning, seen in the data

We adjusted speed and control gains through physical potentiometers, then compared the requested turn with the measured line error. The goal was quick correction without unstable oscillation.

P

Proportional

Responds to the current distance from the center line. Too low felt slow; too high caused side-to-side hunting.

I

Integral

Accumulates persistent error. We limited the accumulated value to prevent integrator wind-up.

D

Derivative

Responds to rapid error changes. It reduced overshoot, but noisy sensors could also create sharp corrections.

How we tuned it

  1. Calibrate every photoresistor on both the light floor and dark line.
  2. Increase proportional response until tracking is firm, then back off when oscillation becomes excessive.
  3. Add only enough derivative control to calm overshoot without amplifying noisy readings.
  4. Keep integral action limited, test each course again, and adjust speed for its physical demands.

04 · Implementation

What changed in our control system

The attached C++ files do not contain Bluetooth code, so the live graphing is shown as a separate test tool rather than part of the onboard firmware.

Weighted sensor position 

float numerator =
              LDR[left] * left +
              LDR[center] * center +
              LDR[right] * right;
            
            error = numerator / denominator
                  - totalPhotoResistors / 2;

Nearby sensor strengths contribute to a smoother position estimate instead of reducing the line to only left, center, or right.

PID protection 

Turn = error * kP
                 + sumerror * kI
                 + (error - lasterror) * kD;
            
            if (sumerror > 5) sumerror = 5;
            else if (sumerror < -5) sumerror = -5;
            
            if (error == 0) sumerror = 0;

The integral value is bounded and reset at center, limiting wind-up that could keep steering after the robot recovered.

Differential steering 

if (Turn < 0) {
              M1P = -Turn;
              M2P = Turn;
            } else if (Turn > 0) {
              M1P = -Turn;
              M2P = Turn;
            }

The signed turn correction changes the two motor commands in opposite directions, steering without a separate mechanical steering system.

07 · Reflection

What we would improve

With the limited amount of time provided in the class, we did the best we could to turn an ambitious concept into a working competition robot. We learned that control ideas cannot be separated from the physical system carrying them out.

For future projects, we would consider the limitations of our equipment much earlier. Our motors, photoresistors, and ESP32 could not always respond as powerfully or consistently as the ideas we were trying to implement required. Earlier testing of torque, minimum usable motor speed, sensor response, noise, and processing limits would help us choose a design that matches the hardware and leave more time for reliable tuning.
